# Deployment Checklist

This document tracks every pre-deployment check required before triggering each CI/CD step.
Keep this updated as the project grows.

---

## How to Use This Document

Before triggering any CI/CD job from GitHub Actions:
1. Find the relevant section below
2. Go through every checkbox
3. Only trigger the job when all boxes are checked

---

## Job 1: `deploy-infrastructure`

Deploys AWS infrastructure via CDK (ECR repo, ECS cluster, task definition, IAM roles, log group).

### GitHub Secrets
- [ ] `AWS_ACCESS_KEY_ID` — IAM user access key added to GitHub Secrets
- [ ] `AWS_SECRET_ACCESS_KEY` — IAM user secret key added to GitHub Secrets
- [ ] `AWS_REGION` — e.g. `ap-south-1` added to GitHub Secrets
- [ ] `AWS_ACCOUNT_ID` — 12-digit AWS account number added to GitHub Secrets

### IAM User Permissions
- [ ] IAM user (`github-actions-user`) has `AdministratorAccess` policy attached
- [ ] Access keys are active (not deactivated)

### CDK Files in Repo
- [ ] `infrastructure/app.py` exists
- [ ] `infrastructure/cdk.json` exists — `"app"` field set to `"uv run python app.py"`
- [ ] `infrastructure/pyproject.toml` exists — contains `aws-cdk-lib` and `constructs`
- [ ] `infrastructure/uv.lock` exists — generated by running `uv sync` locally in `infrastructure/`
- [ ] `infrastructure/stacks/__init__.py` exists
- [ ] `infrastructure/stacks/ecr_stack.py` exists
- [ ] `infrastructure/stacks/ecs_stack.py` exists

### CDK Stack Design
- [ ] `EcrStack` creates repo named `dbt-snowflake` with lifecycle rule (keep last 5 images)
- [ ] `EcsStack` uses default VPC (no NAT gateway cost)
- [ ] Fargate task definition: 0.5 vCPU, 1 GB RAM
- [ ] ECS execution role has `AmazonECSTaskExecutionRolePolicy`
- [ ] ECS task role has `AmazonS3ReadOnlyAccess`
- [ ] CloudWatch log group retention set to 1 week (cost control)

### After This Job Completes
- [ ] Note the ECR repository URI from CloudFormation outputs
  - Format: `<account_id>.dkr.ecr.<region>.amazonaws.com/dbt-snowflake`
- [ ] Verify in AWS Console → ECR → `dbt-snowflake` repo exists
- [ ] Verify in AWS Console → ECS → cluster `dbt-snowflake-cluster` exists
- [ ] Verify in AWS Console → ECS → task definition `dbt-snowflake-task` exists

## Job 2: `build-and-push-image`

Builds the dbt Docker image and pushes it to ECR.

### Prerequisite
- [ ] Job 1 (`deploy-infrastructure`) has been run successfully — ECR repo must exist before pushing

### GitHub Secrets
- [ ] `AWS_ACCESS_KEY_ID` ✅ (same as Job 1)
- [ ] `AWS_SECRET_ACCESS_KEY` ✅ (same as Job 1)
- [ ] `AWS_REGION` ✅ (same as Job 1)

### Files Required in Repo Root
- [ ] `Dockerfile` exists
- [ ] `entrypoint.sh` exists
- [ ] `pyproject.toml` exists (copied into Docker image)
- [ ] `uv.lock` exists (copied into Docker image — needed for `uv sync --frozen`)
- [ ] `aws_snowflake_dbt/` folder exists (copied into Docker image)
- [ ] `aws_snowflake_dbt/packages.yml` exists (needed for `dbt deps` inside Docker build)

### Dockerfile Checks
- [ ] Base image: `python:3.12-slim`
- [ ] `uv` installed inside image
- [ ] `uv sync --frozen --no-dev` used (reproducible, no dev dependencies)
- [ ] `dbt deps` runs inside image build (installs `dbt_utils`)
- [ ] `entrypoint.sh` copied and made executable (`chmod +x`)
- [ ] `WORKDIR` set to `/app/aws_snowflake_dbt` before entrypoint

### entrypoint.sh Checks
- [ ] Writes `~/.dbt/profiles.yml` from environment variables at container startup
- [ ] Uses `exec uv run dbt "$@"` — passes dbt command from Airflow as argument
- [ ] All 5 Snowflake env vars referenced: `SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`, `SNOWFLAKE_PASSWORD`, `SNOWFLAKE_ROLE`, `SNOWFLAKE_WAREHOUSE`

### After This Job Completes
- [ ] Verify in AWS Console → ECR → `dbt-snowflake` → image with tag `latest` exists
- [ ] Image also tagged with git commit SHA for traceability

## Job 3: `run-dbt-pipeline`

Runs the full dbt pipeline directly on the GitHub Actions runner (without ECS).
Used as a quick test / fallback option.

### GitHub Secrets
- [ ] `SNOWFLAKE_ACCOUNT` added to GitHub Secrets
- [ ] `SNOWFLAKE_USER` added to GitHub Secrets
- [ ] `SNOWFLAKE_PASSWORD` added to GitHub Secrets
- [ ] `SNOWFLAKE_ROLE` added to GitHub Secrets
- [ ] `SNOWFLAKE_WAREHOUSE` added to GitHub Secrets

### Snowflake Prerequisites
- [ ] Raw source tables loaded in `GLUE_DATA.ORDERS.*`
  - ORDERS, ORDER_ITEMS, CUSTOMERS, PRODUCTS, CATEGORIES, DEPARTMENTS
- [ ] `ANALYTICS` database exists in Snowflake
- [ ] Snowflake role has access to both `GLUE_DATA` and `ANALYTICS` databases

### dbt Project Checks
- [ ] `aws_snowflake_dbt/packages.yml` exists with `dbt-labs/dbt_utils==1.3.0`
- [ ] `aws_snowflake_dbt/dbt_project.yml` has correct schema config:
  - staging → `ANALYTICS.STAGING`
  - dimensions → `ANALYTICS.DIMENSIONS`
  - facts → `ANALYTICS.MARTS`
- [ ] All staging models have no `LIMIT` clause
- [ ] All 4 snapshot files exist under `aws_snowflake_dbt/snapshots/`
- [ ] All 4 dimension models exist under `aws_snowflake_dbt/models/marts/dimensions/`
- [ ] `fact_sales.sql` exists under `aws_snowflake_dbt/models/marts/facts/`

### dbt Run Order (enforced by workflow steps)
```
dbt run --select staging
    ↓
dbt snapshot
    ↓
dbt run --select marts.dimensions
    ↓
dbt run --select marts.facts
    ↓
dbt test
```

### After This Job Completes
- [ ] Verify in Snowflake → `ANALYTICS.STAGING.*` tables have data
- [ ] Verify in Snowflake → `ANALYTICS.SNAPSHOTS.*` tables have data
- [ ] Verify in Snowflake → `ANALYTICS.DIMENSIONS.*` tables have data
- [ ] Verify in Snowflake → `ANALYTICS.MARTS.FACT_SALES` has data
- [ ] All dbt tests pass (no failures in workflow logs)

## Job 4: `deploy-dags`

Uploads Airflow DAG files from the repo to S3. EC2 cron job syncs from S3 to `~/airflow/dags/` every 5 minutes.

### Prerequisite
- [ ] S3 bucket `airflow-dags-data-engineering` exists
- [ ] EC2 IAM role (`airflow-ec2-role`) has `AmazonS3FullAccess` (to read from this bucket)
- [ ] EC2 cron job is set up (see EC2 Setup section below)

### GitHub Secrets
- [ ] `AWS_ACCESS_KEY_ID` ✅ (same as Job 1)
- [ ] `AWS_SECRET_ACCESS_KEY` ✅ (same as Job 1)
- [ ] `AWS_REGION` ✅ (same as Job 1)
- [ ] `AIRFLOW_DAGS_BUCKET` — value: `airflow-dags-data-engineering`

### Files Required in Repo
- [ ] DAG files exist under `airflow/dags/` in the repo
- [ ] `airflow/dags/dbt_snowflake_pipeline.py` exists

### After This Job Completes
- [ ] Verify in AWS Console → S3 → `airflow-dags-data-engineering/dags/` → DAG files exist
- [ ] Wait up to 5 minutes for EC2 cron to sync
- [ ] Verify in Airflow UI → DAGs → `dbt_snowflake_pipeline` appears

## EC2 Airflow Setup (One-Time)

Steps to run once on the EC2 instance after launch.

### Install and Start Airflow (Docker)
```bash
# SSH into EC2
ssh -i your-key.pem ec2-user@<ec2-public-ip>

# Start Airflow (after EC2 restart)
cd ~/airflow
docker-compose up -d
```

### Install Cron (if not present)
```bash
sudo yum install cronie -y
sudo systemctl start crond
sudo systemctl enable crond
```

### Set Up S3 Sync Cron Job (run once)
```bash
(crontab -l 2>/dev/null; echo "*/5 * * * * aws s3 sync s3://airflow-dags-data-engineering/dags/ ~/airflow/dags/ --delete --exclude '*.pyc' >> ~/airflow/logs/s3_sync.log 2>&1") | crontab -
```

### Verify Cron Was Added
```bash
crontab -l
```

### Airflow Variables to Add (Admin → Variables → + Add)

| Key | Value |
|---|---|
| `AWS_REGION` | `ap-south-1` |
| `ECS_CLUSTER` | `dbt-snowflake-cluster` |
| `ECS_TASK_DEFINITION` | `dbt-snowflake-task` |
| `ECS_CONTAINER_NAME` | `dbt-snowflake` |
| `ECS_SUBNET_ID` | your public subnet ID |
| `ECS_SECURITY_GROUP_ID` | your security group ID |
| `SNOWFLAKE_ACCOUNT` | your Snowflake account identifier |
| `SNOWFLAKE_USER` | your Snowflake username |
| `SNOWFLAKE_PASSWORD` | your Snowflake password |
| `SNOWFLAKE_ROLE` | your Snowflake role |
| `SNOWFLAKE_WAREHOUSE` | your Snowflake warehouse |

### Airflow AWS Connection (Admin → Connections → + Add)
```
Connection Id  : aws_default
Connection Type: Amazon Web Services
Access Key     : (leave EMPTY — IAM Role handles this)
Secret Key     : (leave EMPTY — IAM Role handles this)
Extra          : {"region_name": "ap-south-1"}
```

### After EC2 Restart (every time)
- [ ] EC2 public IP changes — use new IP to access Airflow UI
- [ ] Run `cd ~/airflow && docker-compose up -d` to restart containers
- [ ] Access UI at `http://<new-public-ip>:8080`

## Common Issues and Fixes

| Issue | Cause | Fix |
|---|---|---|
| `ECR repository not found` | Job 2 triggered before Job 1 | Run `deploy-infrastructure` first |
| `uv.lock not found` | Lock file not committed | Run `uv sync` locally, commit `uv.lock` |
| `CDK VPC lookup failed` | `AWS_ACCOUNT_ID` secret missing | Add `AWS_ACCOUNT_ID` to GitHub Secrets |
| `dbt deps failed` | `packages.yml` missing | Ensure `aws_snowflake_dbt/packages.yml` exists |
| `Snowflake connection failed` | Wrong account identifier format | Use format: `<locator>.<region>` e.g. `abc123.ap-southeast-1` |
| `dbt test failures` | Data quality issues or LIMIT clause left in staging | Remove LIMIT from all staging models |
| `Permission denied on ECR push` | IAM user missing ECR permissions | Attach `AmazonEC2ContainerRegistryFullAccess` |
| `crontab: command not found` | cronie not installed on Amazon Linux | Run `sudo yum install cronie -y && sudo systemctl start crond` |
| `Invalid crontab file` | Cron command pasted with line break | Paste as single line — no line breaks |
| `DAG not appearing in Airflow UI` | Cron hasn't synced yet or S3 upload failed | Wait 5 mins, check `~/airflow/logs/s3_sync.log` on EC2 |
| `ECS task fails immediately` | Snowflake env vars not set in Airflow Variables | Add all 5 Snowflake variables in Admin → Variables |
| `Airflow containers stopped after EC2 restart` | Docker doesn't auto-start | SSH in and run `cd ~/airflow && docker-compose up -d` |
